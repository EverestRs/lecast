## 缺陷背景摘要

### A. 安全类
1. **同源 XSS 链路（高危）**：`GET /api/slide/html` 将 AI 生成/用户编辑的 HTML 原样输出（`routers/slide.py`），iframe 无 `sandbox`、无 CSP → 幻灯片内脚本运行于应用同源，可读取 localStorage 中的 apiKey。
2. **API Key 走 URL query**：分章/幻灯片/讲解稿/TTS 的 generate-all 与 regenerate 共 8 处 `?apiKey=` → 泄露至服务器访问日志、代理、浏览器历史。
3. **CORS 全开 + API 无鉴权**：`main.py` 中 `allow_origins=["*"]` 且 `allow_credentials=True`（无效组合）。
4. **innerHTML 注入面**：`showToast` 直接渲染 message；task_list.js 将 taskId 未转义拼入内联 onclick。

### B. 功能 Bug
5. 轮播 indicators 与 prev/next 控件缺 `data-bs-target`，Bootstrap 5 下点击失效。
6. TTS"暂停"按钮实为重播（pause 后重新 new Audio 从头播放），无进度条。
7. 4 个 loadXxx 仅认 `code===200`，不检查 `r.ok`；失败后列表区永久空白且无重试；422 返回 `{detail}` 报 undefined。
8. `validateStep`/`jumpToStep` 依赖全局数组，存在加载竞态误拦。
9. 删除最后一页唯一任务后停留越界页码，表格空白。
10. 视频导出串行长请求无进度/取消/防重复。
11. 仅 404 handler 且 error.html 文案硬编码"404"，500 时返回默认 JSON。

### C. 交互体验
12. taskCreate 页无"配置 SK"入口与状态指示。
13. 长操作仅按钮 spinner，无进度反馈。
14. 覆盖性操作（重新划分章节、各步重新生成）无二次确认。
15. 章节预览截断 200 字后无全文入口；任务不可重命名；各资源无新增/删除/排序（本次不做，见 Decisions）。
16. 上传仅 UTF-8（GBK 乱码无提示）；未在 window 级阻止 drop。
17. 步骤位置不进 URL，刷新被重置；step-item 无键盘可访问性；移动端 iframe 固定 500px 高比例失衡。

### D. 工程质量
18. 第三方库全走 CDN（jsdelivr / plyr.io），无 SRI、无本地回退 → 内网/离线不可用；Plyr 全站加载但仅 Step6 使用。
19. escapeHtml 两文件重复定义；fetch 样板大量重复无统一封装。

## Phase 1：安全（最高优先）✅ 已完成

### 1.1 幻灯片 XSS 沙箱化 *（无依赖）*
- 后端 `routers/slide.py` `get_slide_html`：HTMLResponse 增加响应头
  `Content-Security-Policy: sandbox allow-scripts allow-popups`
  （不给 allow-same-origin → 幻灯片运行于 opaque origin，脚本动画保留但无法读取应用源的 localStorage/cookie/DOM）。
- 前端 `task_create_steps.js` `renderSlideArea` 的 iframe 增加 `sandbox="allow-scripts allow-popups"` 属性（纵深防御）。
- 验证：预览新标签页打开幻灯片仍可看；幻灯片内访问 parent/localStorage 被隔离。

### 1.2 API Key 从 URL 迁移到请求头 *（前后端同步上线）*
- 后端 8 处签名 `api_key: str = Query(..., alias="apiKey")` 改为 `api_key: str = Header(..., alias="X-API-Key")`：
  - `section.py` L24（split）、L129（regenerate）
  - `script.py` L23（generate-all）、L125（regenerate）
  - `slide.py` L24（generate-all）、L143（regenerate）
  - `tts.py` L24（generate-all）、L109（regenerate）
- 前端 `task_create_steps.js` 8 处调用（splitSections/regenSection/genSlides/regenSlide/genScripts/regenScript/genTTS/regenTTS）：URL 删除 apiKey 参数，fetch 增加 `headers: { 'X-API-Key': apiKey }`。
- 注：Phase 2 的 apiFetch 封装将接管 header 附带逻辑，此处先直改。

### 1.3 Toast/错误文案转义 *（无依赖）*
- `escapeHtml` 移入 common.js（common.js 先于页面 JS 加载），删除 task_create.js 与 task_list.js 中的重复定义。
- common.js `showToast`：message 由 innerHTML 直插改为转义后插入。
- `task_list.js` `loadTasks` 错误分支：补缺失的 `</tr>`，err.message 转义。

### 1.4 CORS 收敛 *（可选决策项）*
- `main.py`：删除 `allow_credentials=True`；推荐直接移除 CORSMiddleware（同源应用无需 CORS）。

**Phase 1 验证**
1. Step3 幻灯片 iframe 内执行 `localStorage.getItem('apiKey')` 应抛错或为 null；网络面板确认 generate/regenerate 请求 URL 无 apiKey、Header 含 X-API-Key 且功能正常。
2. 触发含 `<img src=x onerror=alert(1)>` 文案的错误 → toast 显示纯文本不执行。

> 落实情况：两项均已实测通过（2026-08-25，浏览器 + 网络面板核验）。

### 2.3 统一 apiFetch + 加载态/重试 *（依赖 1.2 header 约定）*
- common.js 新增 `apiFetch(url, options)`：

  - 检查 r.ok → 解析 JSON → 校验 code===200，失败抛归一化 Error（兼容 `{detail}` 422 结构）
- 改造 7 个加载函数：loadSections / loadSlides / loadScripts / loadTTS / loadTasks / checkPptxStatus / checkVideoStatus

### 2.4 跳步校验竞态修复 *（依赖 2.3）*

### 2.5 删除越界页回退
- `loadTasks` 缓存当页记录数 lastPageCount；confirmDelete 成功且 `lastPageCount===1 && currentPage>1` 时回退 loadTasks(currentPage-1)。

### 2.6 服务端错误页

## Decisions
- 不引入前端构建链/Vue 迁移；内联 onclick 体系保留（新增代码除外）。
- 不做用户登录鉴权（LAN 信任模型，超出本次范围）。
- 幻灯片沙箱采用"allow-scripts + opaque origin"折中：保留 AI 生成的 CSS/JS 动画效果。
- API Key 仍存 localStorage（配合 1.1 沙箱后风险可控；改 sessionStorage 会牺牲刷新免输）。
- 任务/章节/幻灯片等的重命名与新增/删除/排序能力本次不做。

## Further Considerations
1. 视频导出升级为后台任务 + 轮询（真正解决数分钟阻塞）：工作量大，建议二期单独任务。
2. CORS 处置：推荐删除整个中间件（同源应用）；若未来前后端分离部署再按需加回。
