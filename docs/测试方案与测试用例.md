# v2 测试方案与测试用例

> 适用版本：2026-08-26（Phase 1-6 全部落地 + StepFun/MiMo 切换后）
> 执行环境：Windows + conda 环境（Python 3.10）

---

## 1. 测试对象与目标

| 项 | 内容 |
|---|---|
| 被测系统 | `v2/` 课映（Markdown → 有声教学视频），FastAPI + SQLite + Jinja2 |
| 核心链路 | 上传 → 分章(LLM) → 幻灯片(LLM) → 讲解稿(LLM) → TTS(MiMo) → 导出(Playwright+FFmpeg/PPTX) |
| 测试目标 | ① 验证 6 步流水线功能正确性与失败传播；② 验证 Phase 1-6 修复项无回归（失败占位、级联失效、产物新鲜度、门禁安全、异步作业、落盘迁移）；③ 建立可持续回归的自动化基线 |

## 2. 现有测试基线（已存在，21 例）

| 文件 | 覆盖点 |
|---|---|
| `tests/test_api_tasks.py` | healthz、上传编码/空内容校验、上传成功、重命名校验、音色校验、LIKE 转义搜索 |
| `tests/test_generation_flow.py` | 分章异步全链路（mock）、幻灯片部分失败落 failed 占位、章节移动/删除级联清下游、单章保护 |
| `tests/test_jobs.py` | JobRunner 互斥拒绝、终态后可重提、未知 step 拒绝、失败捕获、快照空值 |
| `tests/test_scripts_and_qwen.py` | scripts 纯函数（配对/缺失/断号/坏音频）、LLM 输出清洗（fence/花括号截取/报错附原文）、build_pairs 空音频 |
| `test/test_stepfun_live.py` | 真实密钥三层联调（连通性 / 分章 JSON / HTML 完整性），手工运行 |

**识别的覆盖缺口（本方案补齐）**：访问门禁与登录安全（Phase 3 全空白）；讲解稿生成链路；TTS 生成/播放/双密钥回退/懒迁移；dump 导出严格校验矩阵；has-final/has-pptx 新鲜度；删任务磁盘清理；上传大小限制；分页；幻灯片 CSP 头。

## 3. 分层测试策略

| 层级 | 手段 | 范围 | 依赖 |
|---|---|---|---|
| **L0 单元** | pytest，直接调用函数/类 | JobRunner、scripts 纯函数、`clean_json_response`/`parse_json_str`、`_safe_next` | 无外部依赖 |
| **L1 API 集成** | pytest + `TestClient`，mock `chat`/`synthesize`，真实 SQLite | 全部 41 个 REST 端点的契约、校验、状态机、级联、文件落盘 | 仅本地 DB（`data/app.db`） |
| **L2 E2E** | 浏览器手工（或 Playwright 脚本） | 页面渲染、向导交互、SK 弹窗、步骤守卫、刷新恢复、移动端 | 本地起服务 |
| **L3 真实联调** | 独立脚本 + 冒烟 | StepFun/MiMo 真实调用、FFmpeg 全链路导出 MP4/PPTX | 真实密钥 + FFmpeg + Playwright chromium |

Mock 边界原则：**只 mock 网络边界**（`llm.chat`、`tts_api.synthesize`），DB、JobRunner 线程、文件系统全部走真实实现，保证失败传播链可信。

## 4. 环境准备

```powershell
# 1. 依赖（已装可跳过）
conda run -n <环境名> python -m pip install -r requirements.txt
conda run -n <环境名> python -m playwright install chromium
# 2. FFmpeg 在 PATH 中（L3 需要）

# L0/L1 自动化全量（在项目目录下的 v2/ 中执行）
cd v2
conda run -n <环境名> python -m pytest tests -q

# L3 联调（替换为真实 Key）
conda run -n <环境名> python test\test_stepfun_live.py <STEP_KEY>
```

注意：
- 测试进程会 pop 掉 `APP_ACCESS_TOKEN`/`STEPFUN_API_KEY` 环境变量，门禁用例通过 monkeypatch 注入，互不影响。
- 用例自建任务并以 `P6TEST` 前缀命名，结束自动删除；若中途强杀残留，可在任务列表按 `P6TEST` 搜索清理。
- 若 8000 端口有旧代码服务在跑，先重启再做 L2/L3。

## 5. L0/L1 自动化测试用例

### 5.1 安全门禁（Phase 3 回归）— `tests/test_security_gate.py`

| 编号 | 用例 | 步骤 | 预期 |
|---|---|---|---|
| TC-U-01 | `_safe_next` 防开放重定向 | 参数化：`//evil.com`、`http://evil.com`、空串 → 兜底 `/taskList`；`/taskCreate` → 原样保留 | 全部符合白名单规则 |
| TC-A-02 | 未启用门禁直通 | 不注入口令直接 GET `/taskList` | 200 |
| TC-A-03 | 页面未登录拦截 | 启用门禁后无 Cookie GET `/taskList` | 303 → `Location: /login?next=/taskList` |
| TC-A-04 | API 未登录返回 JSON | 无 Cookie GET `/api/task/list` | 401，`{"code":401}` JSON（非重定向） |
| TC-A-05 | 豁免路径 | 无 Cookie 访问 `/healthz`、`/static/css/style.css`、`/login` | 均 200/正常响应，不拦 |
| TC-A-06 | 错误口令 | POST `/login` token 错误 | 401 页面含"口令错误" |
| TC-A-07 | 正确口令登录 | POST `/login` 正确 token + next 参数 | 303 → next 目标；Set-Cookie `app_token` 含 HttpOnly；随后带 Cookie 访问受保护页 200 |
| TC-A-08 | Cookie 无效再拦截 | 带伪造 Cookie 访问 | 仍被 303/401 拦截 |

## 8. 专项与性能关注点

- **并发互斥**：同一步骤重复提交被拒（TC 已覆盖 JobRunner；E2E 双击按钮观察"正在执行"toast）。
- **N+1 回归**：列表接口 SQL 数应恒定（开启 SQLAlchemy echo 数查询次数，不随任务行数增长）。
- **子进程超时**：构造多页录制验证 record/compose 超时预算公式不被触发误杀。
- **日志滚动**：logs/app.log 超 10MB 自动切割（低优先，抽查即可）。

## 9. 通过标准

1. L0/L1 pytest 全绿（约 50 例），单次运行 < 2 分钟；
2. L2 手工用例全部符合预期，P0/P1 缺陷清零；
3. L3 至少完成 TC-L-01 与 TC-L-03 各一次并在版本发布前复跑；
4. 任何缺陷修复后必须先补对应层级用例再合入。

## 10. 风险与注意事项

- mock 只在 `app.routers.*.chat` / `tts_api.synthesize` 层打桩，勿 patch `httpx.post`（模块级 Client 已改为连接池）；
- TestClient 需 `with` 形式触发 startup（列迁移）才有效；
- 前端 modal fade 过渡期间 programmatic click 可能残留 `.show`（Playwright 需等待过渡）；
- 8000 端口旧进程不改代码热生效，改动后必须重启；
- 测试共享开发库 `data/app.db`，用例均以 P6TEST 前缀隔离并自清理。
